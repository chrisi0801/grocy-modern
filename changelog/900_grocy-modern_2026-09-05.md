- Completely reworked the user interface: modern, mobile first design
  - New design system: all colors, radii, elevations and typography are driven by CSS custom properties (`/public/css/grocy_theme.css`), so re-theming (also via `custom_css.html`) only means overriding a handful of variables
  - New app shell: sticky top bar, a quieter sidebar which can be collapsed to an icon rail, and on phones/tablets a proper off-canvas navigation drawer (swipe or tap outside to close) instead of the menu pushing the page down
  - New bottom tab bar on phones/tablets with the most used views plus a quick action button for purchase / consume / transfer / inventory
  - Tables are rendered as cards on small screens: every cell is labelled with its column header, the row actions move into a footer, empty cells are omitted and a toolbar above the list offers sorting and the table options (both were only reachable via the table header before)
  - Dialogs are shown as bottom sheets on phones
  - Dark mode was rebuilt on top of the same design tokens, so it now covers all components consistently
  - Toasts are collapsed to a single line and expand on tap to reveal the full text and the "Undo" button, instead of covering a good part of a phone screen for 20 seconds
  - The stock overview row actions are down to the quick consume button plus the overflow menu: "Consume all" and "Mark as opened" moved into that menu, which also shrinks the action column on desktop
  - Swipe actions on the cards: swipe left to consume the quick consume amount, swipe right to add to the shopping list. Both trigger the controls that already exist in the row, so the API call, the toast with undo and the permission handling are grocy's own
  - The row actions no longer occupy a row of their own on phones but sit in the top right corner of the card, which brings a stock overview card down from 182px to 127px
- New: Household budget (Grocy Modern only), modelled on the "tracking budget" of [Actual Budget](https://github.com/actualbudget/actual)
  - A shared household budget plus personal budgets per user; everybody with the new permission `BUDGET` can see all budgets, but a personal budget can only be changed by its owner
  - Monthly plan per category (applies from a month on until changed), with an optional carryover of what is left into the next month per category
  - The overview shows planned, spent and remaining per category, the balance and what is really available (balance minus what the plan still needs this month)
  - Transfers between budgets (e.g. pocket money), refunds lower the expense category they are booked to
  - Recurring transactions (monthly, quarterly, half-yearly, yearly, also as transfers) are booked automatically when due, missed dates are caught up
  - Reports: income, expenses and net per month and expenses by category, per budget or across all of them
  - Own REST endpoints under `/api/budget/...`; can be disabled with `FEATURE_FLAG_BUDGET`
- Fixed that the route cache was only rebuilt when the version number changed, so new or changed routes of a fork update without a new version led to wrong pages
- New: a connection indicator in the top bar - green (fine), yellow (slow, or a request has been waiting for an answer for more than 2.5 seconds), red (no connection, logged out or the server is down). Tapping it shows the details, the recent problems and a connection test which also detects the typical VPN problem of small requests getting through but large answers not (a too large MTU of the tunnel)
- Fixed that inputs could seem to be ignored on a flaky connection (e.g. while a VPN reconnects after the phone was unlocked): API requests had no timeout and most views only logged a failed request to the browser console, so a tap did nothing, a form stayed disabled and a few hanging requests could block all further ones. Every API request now gives up after 20 seconds, the view's own error handling runs and a toast says what happened
- Fixed that primary (and all other solid) buttons turned Bootstrap blue on hover and, on phones, after being tapped
- New: Profiles (Grocy Modern only) - several completely separate households in one installation, e.g. one per building
  - Every profile is a data directory of its own (`data/profiles/<id>/`) with its own database and files: stock, chores, tasks, calendar, shopping lists, recipes, meal plan, budget and users are separate. The existing data is the main profile and stays as it is; as long as there is no second profile, nothing changes
  - Profiles are created by administrators of the main profile, optionally with a one-time copy of the master data (products, quantity units incl. conversions, product groups, locations, stores, barcodes, product pictures). The creator becomes administrator of the new profile with the same login and is logged in there right away
  - Users and logins are per profile; a browser stays logged in to every profile it was logged in to, and the switcher next to the logo only offers those. The login page has a profile choice
  - Every API request of a page carries the profile the page belongs to (`X-Grocy-Profile`), so a second tab switched to another profile meanwhile can never change the wrong household; API keys (and the iCal link) select their profile on their own
  - Deleting a profile moves its folder to `data/profiles-deleted/`
  - Each profile migrates its database on its first request after an update (also when only used via an API key), guarded by a lock against parallel requests
- New: "Count stock in another unit" below the stock quantity unit of a product (Grocy Modern only) - once a product was in stock, grocy offers only units with a conversion; this asks for the new unit and how the two relate (e.g. 1 pack = 8 rolls), creates the product's unit conversion and saves the product with the new unit, so grocy converts stock, shopping lists and recipes by itself
- New: Barcode lookup (Grocy Modern only) - "E" in the dialog for unknown barcodes now asks a chain of sources instead of one plugin
  - First the other profiles (a product the other household already has, including its picture), then the Open Facts databases with one universal lookup: food, cosmetics/drugstore, other products (household goods), pet food
  - Optionally a web search with AI (Claude with web search and web fetch) for barcodes the free sources do not know - only on request, with an API key set up by an administrator of the main profile (or `ANTHROPIC_API_KEY`), a choice of model (Opus 5.5, Sonnet 5.5, Haiku 5.5), web searches per lookup and a monthly limit; the cost of each lookup is calculated from its actual tokens and searches, shown right after it and summed up per month on the settings page
  - An optional hint from the package (brand, product name) lets the AI search for the product itself and check its barcode; Claude explains in a sentence what it found or searched, and when a search ends without an answer (no report, declined, cut off, too long) the reason is shown instead of a plain "not found"
  - Nothing is created unconfirmed: the result is a preview with name (incl. brand), package size, minimum stock amount and proposals for product group, location, quantity unit and due days (or "never overdue"), mapped to what the profile already has. Proposals improve over time - choices are remembered per Open Facts category, and changing the group in the preview brings along the location, unit and due days other products of that group have (so a non-food product no longer asks for a due date on every purchase). An existing product of the same name is offered to receive the barcode instead
  - After confirming, the page the lookup came from continues with the new product selected - matched by its exact name first, so "Milch" no longer selects "Buttermilch"
